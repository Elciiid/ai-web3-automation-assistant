# Project Context

Master handoff memory for AI Web3 Automation Assistant.

## App Purpose

AI Web3 Automation Assistant is an AI-powered blockchain automation workspace.

Users should be able to:

- Monitor blockchain wallets.
- Create automation rules with natural language.
- Review structured rule previews before saving.
- Inspect transactions with AI-generated explanations.
- Receive operational notifications about wallet activity.
- Manage monitored wallet records.

The product is not a crypto exchange, NFT marketplace, token swap app, or generic analytics dashboard. It is a focused AI infrastructure workspace for blockchain operations.

## Current Architecture

The app uses Next.js App Router with a Supabase-backed backend foundation.

- Public routes: landing page, sign-in, and sign-up.
- Protected workspace routes: dashboard, wallets, automations, builder, transactions, notifications, and settings.
- Authentication: Supabase email/password auth with protected route middleware.
- Backend data: Supabase Postgres tables protected with RLS.
- Blockchain enrichment: Alchemy HTTP APIs are used from server-side services only when `ALCHEMY_API_KEY` is configured.
- API routes: Next.js route handlers return `{ data }` on success and `{ error }` on failure.
- Service layer: database logic lives in `src/services`, not directly in React components.
- Frontend data layer: small hooks call the API and keep screens incremental and maintainable.

## Backend-Connected Systems

- Supabase Auth sign-in/sign-up.
- Protected dashboard routing.
- Wallet reads through `GET /api/wallets`.
- Wallet create through `POST /api/wallets`.
- Wallet delete through `DELETE /api/wallets/[id]`.
- Wallet refresh/enrichment through `POST /api/wallets/[id]/refresh`.
- Automation list/create/edit/status/delete through `/api/automations`.
- Transaction list/detail reads through `/api/transactions`.
- Notification feed/read state through `/api/notifications`.
- Backend AI rule parsing route through `/api/ai/parse-rule`.

## Frontend Screens

- Landing page: premium product intro, workflow preview, feature sections, CTA.
- Auth: sign-in/sign-up screens connected to Supabase Auth.
- Dashboard: AI Command Center, backend-backed automations, wallet summary, priority activity, notifications.

## Design Philosophy

The product should feel like:

- Minimal but premium.
- Calm Web3 infrastructure.
- AI command center, not admin dashboard.
- Fintech-grade hierarchy and spacing.
- Soft dark atmosphere with restrained depth.
- Uniswap-inspired polish without copying swap UX.

Avoid:

- Crypto casino visuals.
- Cyberpunk neon.
- Generic admin dashboard patterns.
- Excessive gradients, glow, motion, and boxed sections.
- Hover states on non-interactive surfaces.

## Mocked or Placeholder Boundaries

- Wallet records are real Supabase rows. Native balance, estimated USD value, token summaries, and recent transfers are provider-derived when `ALCHEMY_API_KEY` is configured.
- Wallet risk labels and 24h changes are still simplified placeholders.
- Transactions are real Supabase rows. They can be seeded demo data or provider-ingested rows from wallet enrichment.
- AI rule parsing uses deterministic backend logic, not a real AI provider yet.
- Transaction explanations are seeded/demo summaries, not generated by an AI model yet.
- Automation rules are stored, but no worker executes rules against blockchain events yet.
- Notifications are stored and displayed, but not delivered to Slack, Telegram, email, webhooks, or push.

## Known Implementation Notes

- The auth left-panel divider was removed to prevent a short-lived vertical-line flash during route/session transitions.
- Transaction rows were refactored so chain badges, wallet names, hashes, values, and status pills do not overlap in narrow dashboard cards.
- If a `__webpack_modules__[moduleId] is not a function` runtime error appears during development, restart the dev server and clear stale `.next` output if needed. This is usually a stale Next.js dev chunk/HMR issue.
