# AGENTS.md

## After-Code Explanation Rule

After every coding task, refactor, bug fix, or file change, explain the work to me in beginner-friendly but developer-accurate language.

Do not only say what files changed. Teach me what the code does.

Use this format after every completed task:

### 1. What I changed
- Briefly list the main changes.

### 2. Why I changed it
- Explain the reason behind the changes.
- Connect the changes to the project goal.

### 3. How the code works
- Explain the important components, functions, hooks, routes, or files.
- Use simple language.
- Avoid unexplained jargon.
- If jargon is necessary, define it.

### 4. How the user experiences it
- Explain what changed in the UI/UX.
- Describe what the user can now see or do.

### 5. Files changed
- List each modified file.
- Explain the purpose of each file in one sentence.

### 6. How to test it
- Give exact commands if relevant.
- Give manual testing steps.

### 7. What I should learn from this
- Explain the key frontend/backend/software engineering concept involved.

### 8. Next recommended step
- Suggest only one next step.
- Keep it practical.

Rules:
- Keep explanations clear and structured.
- Do not overwhelm me with unnecessary theory.
- Do not skip this explanation unless I explicitly say "skip explanation."
- If something was not completed, say it clearly.
- If mock data was used, say it clearly.
