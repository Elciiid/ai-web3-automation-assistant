# Design System

## Product Feeling

AI Web3 Automation Assistant should feel like a premium AI infrastructure workspace for blockchain operations.

The interface should be:

- Minimal.
- Restrained.
- Calm.
- Precise.
- Premium.
- Operational.
- Web3-native without being flashy.

## Visual Direction

Use Uniswap as inspiration for softness, dark atmosphere, rounded surfaces, and interaction quality, but do not copy its token swap product or colorful token background.

The app should combine:

- AI workspace clarity.
- Fintech dashboard discipline.
- Developer-tool structure.
- Web3 product polish.

## Background

Use a soft dark environment with:

- Subtle noise texture.
- Low-opacity radial lighting.
- Minimal atmospheric depth.
- No visible grid or box pattern.
- No loud decorative gradients.
- No floating token-style visuals.

The background should support the content, not compete with it.

## Surfaces

Use calm layered surfaces:

- Dark translucent panels.
- Subtle borders.
- Light backdrop blur only where useful.
- Small, controlled shadows.
- Rounded cards with consistent radius.

Avoid making every card look clickable. Static information surfaces should stay visually still.

## Interaction Rules

Only interactive elements should react to hover or focus:

- Buttons.
- Links.
- Tabs.
- Sidebar items.
- Search/input controls.
- Clickable transaction rows.
- Toggle/edit/delete controls.

Hover states should be subtle:

- Slight background change.
- Slight border change.
- No large movement.
- No heavy glow.
- No exaggerated animation.

## Navigation

Navigation should feel structural and quiet.

- Sidebar should recede behind content.
- Only the active route should stand out clearly.
- Inactive nav items should be low-contrast but readable.
- Topbar should feel integrated, not like a generic admin header.
- Search should feel like a calm workspace affordance.

## Typography

Typography should be readable and deliberate.

- Use strong hierarchy for page titles and the AI Command Center.
- Keep secondary section headings quieter.
- Avoid oversized dramatic text inside dashboards.
- Use consistent sizes and weights.
- Do not use negative letter spacing.

## AI Command Center

The AI Command Center is the hero interaction across the product.

It should clearly communicate:

1. User enters natural language.
2. AI parses the request.
3. Structured rule preview appears.
4. User saves automation.
5. Active rule and notification state update.

This area can have slightly more emphasis than other panels, but it should remain restrained.

## Components

Preferred patterns:

- Cards for repeated items and focused panels only.
- Drawers/modals for transaction details and editing flows.
- Badges for status and severity.
- Icon buttons for compact actions.
- Text buttons only for clear commands.
- Skeletons/loading states where data is pending.
- Transaction rows should keep identity, value, status, and explanation in stable zones so labels, badges, hashes, and wallet names never overlap.
- Auth surfaces should avoid strong internal divider lines because they can flash during route/session transitions.

Avoid:

- Cards inside cards.
- Decorative gradients inside every panel.
- Hover effects on static cards.
- Excessive glassmorphism.
- UI that feels like a crypto casino or NFT landing page.

## Color Guidance

Base palette:

- Dark neutral background.
- White text with varied opacity.
- Soft fuchsia accent for AI/Web3 emphasis.
- Green for active/success.
- Yellow for warning/review.
- Red only for destructive/error states.
- Cyan/blue only for neutral metadata.

Use accent colors sparingly.

## Motion

Motion should be fast, subtle, and purposeful.

Use motion for:

- Route transitions.
- Drawer/modal entrance.
- Parsing/loading feedback.
- Small state changes.

Avoid:

- Constant ambient animations.
- Large hover movement.
- Decorative motion without product meaning.
